# v0.4 — Hypothesis Reliability / Stress-Testing Engine

Status: released in SciForge V0.4 public beta (package version `0.4.0`). Tested offline (FakeModelClient /
`httpx.MockTransport`); no live xAI run has been made with this engine yet.

Every hypothesis SciForge outputs is an **Unvalidated, AI-generated hypothesis for further investigation — not a
validated discovery or scientific finding.** The label is set by code; the model cannot set or change it.

Code: `app/sciforge/hypothesis_validation.py` (all deterministic checks), `app/sciforge/stages/hypotheses.py`
(generation → critic → revision), prompts in `app/sciforge/prompts_synthesis.py`
(`HYPOTHESIS_PROMPT_VERSION = "v0.4-hypothesis-1"`), report section H in `app/sciforge/stages/report.py`.

## Pipeline

```
question → extraction (1 call per source) → gaps → hypotheses (generation) → hypothesis_critic
        → hypothesis_revision (only if needed) → report narrative
```

| Stage | Calls | Receives | Returns |
|---|---|---|---|
| `hypotheses` | 1 (batched, ≤ 5 hypotheses) | question definition, accepted evidence (opaque `ev_…` ids, claim/finding/category/confidence and the code-verified exact quote as `verified_quote`), accepted gaps | structured hypotheses |
| `hypothesis_critic` | 1 (batched over all candidates) | same evidence + gaps + the candidates (with their deterministic flag codes) | per candidate: 8 checks (`pass` / `fail` / `uncertain` + short explanation), `unsupported_evidence_ids`, `substantive_problems` |
| `hypothesis_revision` | 0 or 1 (batched over the candidates that need it) | same evidence + gaps + candidates needing revision, their deterministic flags and the (sanitised) critic review | revised hypotheses (same schema) |

The model never receives titles, authors, journals, years, DOIs, PMIDs or URLs: only opaque record/evidence/gap
ids and verified abstract text. `verified_quote` is an exact substring of the abstract checked by code in the
extraction stage (identifier-like substrings redacted). No hidden reasoning is requested or stored; the critic's
explanations are short visible strings, sanitised by code (withheld if they contain bibliographic or identifier
text or unknown ids; truncated to 400 characters).

**Batching.** Critic and revision are each one call for all hypotheses (not one per hypothesis) so the engine
adds at most 2 calls to an investigation and fits the 15-attempt budget.

**Calls per investigation** with S sources: `1 + S + 1 + 1 + 1 + (0 or 1) + 1` = **S + 5** (no revision needed)
or **S + 6**. Web default S = 5 → 10 or 11 attempts. Each call may use one repair retry (JSON/schema failure), so
the uncapped worst case is 2·(S + 6); the unchanged 15-attempt default cap (and the $2 web Live spend cap)
bounds every run. With S ≥ 10 sources, or with repairs, the cap can be reached inside the engine.

**Revision is triggered** for a candidate that has any revisable deterministic flag, **or** any critic verdict
`fail`, **or** a non-empty `substantive_problems` list. `uncertain` verdicts alone do not trigger revision (they
are shown in the report). Hard deterministic failures are rejected at generation and never reach the critic.

**The critic is not re-run on a revised hypothesis** (budget). A revised hypothesis must pass the full
deterministic validation again plus the revision link rules; the report says "the critic was not re-run on the
revision".

## Budget exhaustion and failures (safe behaviour)

All three calls go through the same `call_structured` → budget reservation → attempt/spend accounting as every
other stage (no separate accounting).

| Situation | Behaviour |
|---|---|
| Critic not run (budget exhausted / spend cap) or failed | Candidates with no deterministic flags are kept but marked **"NOT stress-tested: the critic did not review this hypothesis"** (never presented as critiqued; no critic findings shown). Flagged candidates are rejected (`revision_not_run` / `revision_failed`). |
| Critic reviewed only some candidates | status `incomplete`; unreviewed candidates carry the NOT stress-tested note. |
| Revision needed but not run / failed | the candidate is rejected (`revision_not_run` / `revision_failed`; `critic_substantive_problems` if the critic flagged it). |
| Revision returns no item for a candidate | rejected (`revision_missing`). |
| Revised item still fails | rejected (`unresolved_after_revision` + the failing codes). Never silently accepted. |
| Critic found nothing and no flags | original kept, `revision_status` = "no revision required". |

Rejected hypotheses are reported as rejected with reason codes only (no model text). If any candidate is
rejected after generation, the stored critic and revision request prompts are also redacted in
`model_calls.json` (they contained the candidate text).

## Hypothesis object

Model fields (strict schema; any other field is rejected): `hypothesis_id`, `hypothesis`, `evidence_ids` (≥ 1),
`research_gap_id`, `mechanistic_claim_level`, `rationale`, `prediction`, `alternative_explanation`
{`explanation`, `basis` = `evidence` | `inference`, `evidence_ids`}, `falsification_test`
{`manipulated_or_compared`, `measured`, `weakening_result`, `supporting_result`}, `assumptions` (list),
`evidence_limitations` (list, ≥ 1), `confidence` (`low` / `moderate` / `high`).

Added by code: `hypothesis_id` (`hyp_01`…), `label`, `notice`, `supported_claim_level` (+ basis),
`causality_statement`, `source_quality_summary`, final `confidence` and `confidence_detail`
{`proposed_by_model`, `deterministic_ceiling`, `final`, `reasons`, `capped`}, `validation`, `stress_test`
{`critic_status`, `critic_findings`, `substantive_problems`, `unsupported_evidence_ids`, `revision_status`, `note`}.

## Claim-level mapping

Levels (ordered): `observation` < `association` < `mechanistic_support` < `causal_claim`.

Existing evidence items carry no study-design field, so the per-item level is derived conservatively from the
**code-verified exact quote** plus the item's `evidence_category`:

| Evidence item | Level |
|---|---|
| category `inference` or `hypothesis` | observation |
| category `conflicting` | association if the quote has an association cue, else observation (never higher) |
| `established`, quote has an intervention cue (randomised, knockout/knockdown, blockade/blocked, inhibited/inhibitor, antagonist, deficient, deleted, silenced, overexpressed, treated with, administered, exposed to, abolished, prevented, rescued …) | causal-eligible |
| `established`, mechanistic cue (binds, receptor, pathway, signalling, phosphorylation, cleavage, unfolds, conformation, mechanism, mediates, interacts, via …) | mechanistic_support |
| `established`, association cue (associated, correlated, increased/decreased, higher/lower, compared with, versus, differed …) | association |
| otherwise | observation |

The hypothesis's supported level is the maximum over its cited items, except that **`causal_claim` requires
causal-eligible items from ≥ 2 distinct sources labelled "peer-reviewed journal article" and no conflicting item
among the cited evidence**; otherwise it is capped at `mechanistic_support`. Unknown source types (e.g. Demo
Mode, unclassified records) therefore never support `causal_claim`.

- Proposed level above the supported level → flag `claim_level_exceeds_evidence` (no silent upgrade or
  downgrade; revision must lower it, else rejected).
- Below `causal_claim`, unhedged causal language in `hypothesis` or `rationale` → flag
  `unhedged_causal_language`. Lexicon: causes/caused, drives/driven, leads to/led to, is/are responsible for,
  induces, mediates, determines/determined by, triggers, results in, underlies, is required for, produces. A
  match is hedged only if a hedge word appears **earlier in the same sentence** (may, might, could, would,
  possibly, potentially, whether, if, hypothesise/hypothesis, propose, suggest, likely, plausibly, perhaps,
  speculative).
- **Causality statement (code-appended):** below `causal_claim` every hypothesis carries "Causality is not
  established: the cited evidence supports at most X; this hypothesis is stated at the Y level." At
  `causal_claim` it says causality remains untested by SciForge.

## Deterministic validation rules

Hard (rejected at generation, never revised): schema violation / unexpected field / model-supplied bibliographic
field; evidence id that is not an ACCEPTED evidence item (rejected evidence never receives an id, so it cannot be
cited) in `evidence_ids`, `alternative_explanation.evidence_ids` or inline; unknown source or gap id; missing or
unknown `research_gap_id`; no evidence ids; invalid claim level; non-qualitative confidence; bibliographic or
identifier text anywhere in model text — DOI/PMID/URL/ISBN patterns, "et al.", author-year and bare
year-in-parentheses citations "(2019)", the words doi/pmid/isbn/issn (existing v0.3 detectors plus the v0.4
extras); more than 5 hypotheses.

Revisable flags (sent to revision; still present afterwards → rejected):

| Code | Rule |
|---|---|
| `claim_level_exceeds_evidence`, `unhedged_causal_language` | see above |
| `prediction_missing` / `prediction_not_measurable` | empty, or no measurable term (heuristic regex: measure, level, rate, increase, decrease, reduce, elevated, higher, lower, greater, less, smaller, larger, fold, percent/%, compared with/to, relative to, versus, correlat…, threshold, expression, concentration, count, frequency, proportion, amount, abundance, activity, duration, time to, magnitude, differ…, change, score, incidence, prevalence, odds, risk, size, number) |
| `prediction_restates_hypothesis` | Jaccard similarity of normalised content words (lower-cased, ≥ 3 chars, stopwords removed, plural "s" stripped) between prediction and hypothesis ≥ **0.8** |
| `prediction_not_discriminating` | prediction vs alternative explanation Jaccard ≥ 0.8 |
| `falsification_incomplete` / `falsification_not_discriminating` | any of the 4 parts missing/empty; weakening and supporting results identical or Jaccard ≥ 0.8 |
| `alternative_missing` / `alternative_basis_invalid` | empty explanation; basis not evidence/inference; basis evidence without accepted ids; basis inference with ids |
| `procedural_protocol_detail` | wet-lab protocol detail in prediction or falsification test: concentrations (µM, mM, mg/mL, …), volumes (µL, mL), centrifugation (rpm, × g, "centrifuge"), temperatures (°C), incubation times, numbered step lines / "step N" — the test must stay high level |
| `self_labeled_discovery` | discovery/discovered, finding(s), validated, proven/proves, confirms/confirmed, establishes, demonstrates that, breakthrough in hypothesis, rationale or assumptions |
| `hypothesis_asserted_as_fact` | v0.3 assertive-phrasing patterns ("it is established that", "definitively", …) |
| `untraceable_quote` | any quoted span (≥ 12 chars in quotes) that is not an exact substring of the cited evidence's verified quote or verified source text |
| `unsupported_claim` | numbers not present in the cited evidence (v0.3 numeric check) |
| `limitations_missing`, `empty_text` | no evidence limitation; empty text field |

Revision link rules: revised `evidence_ids` must be a subset of the original ids (`revision_added_evidence`
otherwise) and must keep every original link unless the critic listed that exact id in
`unsupported_evidence_ids` (`revision_dropped_supported_evidence`); the research gap may not change
(`revision_changed_gap`). New citations/ids/bibliographic text are caught by the same hard checks.

**Precedence:** the validator outranks both the model's self-assessment and the critic. A critic "pass" never
rescues a deterministic flag; a model-proposed confidence never exceeds the deterministic ceiling.

These lexicons and thresholds are heuristics: they catch common phrasing, not every possible over-claim, and can
occasionally flag acceptable text. They are not semantic entailment checks.

## Confidence (qualitative only)

Final confidence = min(model proposal, deterministic ceiling). Ceiling starts at `high` and is capped by:

| Condition | Ceiling |
|---|---|
| any abstract-only evidence (currently always) | moderate |
| fewer than 2 distinct sources | low |
| no cited source labelled peer-reviewed journal article | moderate |
| all cited sources are preprints | low |
| conflicting evidence cited, or the linked gap records conflicting evidence | low |
| no `established` evidence item cited (indirect support only) | low |
| claim level `causal_claim` | moderate |
| some (not all) cited sources are preprints | one step lower than otherwise |

Both values and the reasons are stored (`confidence_detail`); no numeric probability or percentage is ever
produced (a numeric or "%" confidence from the model is a hard schema failure). Because all evidence is
abstract-only today, the effective maximum is `moderate`.

## Source quality

`source_quality_summary` is written by code: evidence item count, distinct sources, source-type badges (preprints
always "Preprint — not peer-reviewed"), and "all evidence is abstract-only". The default source policy stays
`peer_reviewed_preferred`; preprint-backed evidence lowers the confidence ceiling (table above).

## Report and UI

Section H lists, per accepted hypothesis: heading `hyp_NN — <notice>`, label, candidate hypothesis, claim level +
causality statement, why it was proposed (rationale, research gap, linked evidence), measurable prediction,
alternative explanation + basis, how it could be falsified (4 parts), assumptions, limitations, source quality,
confidence (final / proposed / ceiling reasons), critic review (per-check verdicts), revision status and
validation status; then rejected candidates with reason codes only. Evidence (C/D/E) and research gaps (G) stay
in their own sections. The web Hypotheses tab adds a table (ID, label, claim level, confidence, critic, revision)
above section H. Demo Mode's scripted model includes synthetic critic and revision responders: `hyp_01` passes,
`hyp_02` deliberately over-claims causality, is flagged, criticised and revised (9 attempts total).

## Outputs

`hypotheses.json` adds `engine`, `critic` {status, skip_reason, attempts, repair_attempted, errors}, `revision`
{status, skip_reason, revised, attempts, errors}, `candidates`, `attempts_by_stage`, `notice`; accepted records as
above; rejected records with `rejected_at` (generation / revision / unresolved), reason codes and verdict-only
critic info. `model_calls.json` records every attempt with stage `hypothesis_critic` / `hypothesis_revision`.

## Limitations

- Heuristic lexicons (causal, hedge, measurable, discovery, protocol) and the 0.8 Jaccard threshold.
- Claim level is inferred from quote wording and category, not from a study-design field.
- The critic is itself a model; its verdicts are advisory and are not re-run after revision.
- Abstract-only evidence caps confidence at moderate; no full text.
- No live xAI verification of the new prompts yet.

## Evidence-to-Hypothesis Graph

Code: `app/sciforge/evidence_graph.py` (`GRAPH_VERSION = "v0.4-evidence-graph-1"`, `build_evidence_graph`,
`validate_evidence_graph`, `build_validated_graph`, `graph_json`, `graph_to_dot`, `node_options`,
`node_details`). Built purely by code from the run's structured outputs — eligible verified v0.2 records
(`source_texts.json` entries with status ok), accepted evidence, accepted gaps and accepted v0.4 hypotheses.
**No model call.** Rejected evidence, gaps and hypotheses never enter the graph. Written as
`evidence_graph.json` by `run_model_investigation` (Demo and Live web runs, library use; the v0.2 CLI has no
model stages) and summarised in `report_validation.json` → `evidence_graph`.

### Nodes (id scheme is deterministic)

| Type | Id | Fields |
|---|---|---|
| source | `src:<record_id>` | title, authors, year, journal, doi, pmid, source_url (copied **only** from the v0.2 record), verification_status, source_type (peer-reviewed journal article / preprint / conference paper / book/chapter / unknown, from `source_classification`), source_type_label, preprint_label ("Preprint — not peer-reviewed" or null), abstract_only, access_level, provenance |
| evidence | `ev:<evidence_id>` | source_record_id, claim, finding, **verified_quote** (exact verified substring), evidence_category, confidence, abstract_only, access_level, conflict_note (for category conflicting), provenance |
| gap | `gap:<gap_id>` | gap_statement, why_unresolved, label, confidence, supporting_evidence_ids, conflicting_evidence_ids, provenance |
| hypothesis | `hyp:<hyp_id>` | label, **warning** "Unvalidated, AI-generated hypothesis for further investigation — not a validated discovery or scientific finding.", hypothesis, rationale, evidence_ids, research_gap_id, mechanistic_claim_level, supported_claim_level, causality_statement, confidence (+ proposed/ceiling/reasons), alternative_explanation, assumptions, evidence_limitations, source_quality_summary, critic_status, critic_verdicts (verdicts only), revision_status, stress_test_note, provenance |
| prediction | `pred:<hyp_id>` | parent_hypothesis_id, text |
| falsification_test | `fals:<hyp_id>` | parent_hypothesis_id, manipulated_or_compared, measured, weakening_result, supporting_result |

### Edges (exactly five types; id `type|source|target`)

| Type | Direction | Meaning |
|---|---|---|
| supports | source → evidence | the evidence item's exact quote was verified in this source |
| supports | evidence → hypothesis | the accepted hypothesis cites this accepted evidence |
| motivates | evidence → gap | listed by the accepted gap (`role` supporting / conflicting) |
| addresses | hypothesis → gap | the hypothesis's research gap |
| tests | prediction → hypothesis, falsification_test → hypothesis | each tests its parent hypothesis |
| contradicts | evidence ↔ evidence (stored once, source < target, `bidirectional: true`) | see below |

**Contradictions are never invented.** The pipeline records conflicts in two places: an evidence item's
category `conflicting` (no partner) and an accepted gap's `conflicting_evidence_ids` alongside its
`supporting_evidence_ids`. Only the second is an explicit pairing, so a `contradicts` edge is emitted only
between an id in a gap's `conflicting_evidence_ids` and an id in the same gap's `supporting_evidence_ids`
(`basis: "research_gap_record"`, `recorded_by_gaps`). A `conflicting` item without such a gap record gets a
`conflict_note` on its node and no edge. Demo Mode's synthetic gap_01 records ev_0003 as conflicting with
ev_0001, which produces the demo's single contradiction edge.

### File layout (`evidence_graph.json`)

Sorted keys, 2-space indentation, trailing newline, nodes and edges sorted by id, **no timestamps**:
`graph_version`, `notice`, `id_scheme`, `edge_types`, `contradiction_policy`, `references`
{source_record_ids, evidence_ids, gap_ids, hypothesis_ids}, `counts`, `nodes`, `edges`, `excluded`
[{item, reason, fields?}], `content_sha256` (SHA-256 of canonical nodes+edges+excluded), `validation`
{status passed / passed_with_exclusions / failed, errors, checks}. Building twice from the same inputs is
byte-identical (tested, including shuffled input order and two separate pipeline runs).

### Exclusion (build) and validation

While building, an item is dropped and recorded in `excluded` if: its evidence's source is not an eligible
verified record (`source_not_verified_record`); a gap or hypothesis references evidence/gaps not in the graph
(`gap_references_missing_evidence`, `hypothesis_references_missing_evidence`, `hypothesis_references_missing_gap`);
a hypothesis lacks its prediction or a falsification part; or model-derived text (evidence claim/finding, gap
text, hypothesis text/rationale/assumptions/limitations/alternative, prediction, falsification parts) contains
identifier or citation-like text per the existing detectors (DOI/PMID/URL, "et al.", author-year, "(2019)",
doi/pmid words) → `bibliographic_text_in_model_text`; a dropped hypothesis takes its prediction and
falsification nodes with it. The verified quote is source text, not model text, and is not scanned.

`validate_evidence_graph(graph, inputs)` returns errors for: invalid node/edge ids; unresolved source /
evidence / gap / hypothesis nodes; bibliographic field or source-type / preprint-label mismatch against the
v0.2 record and classification; evidence quote/source mismatch; invalid edge type or direction; dangling
edges; wrong source link; hypothesis evidence edges ≠ its evidence ids; hypothesis without exactly its gap edge
or its prediction + falsification edges; tests edge to the wrong parent; motivates edge not recorded by the
gap; contradicts edge without a gap record; rejected-evidence text present; report citations ≠ graph source
records (source nodes = sources of accepted evidence ∪ verified records resolved in the report's citations);
fabricated citation text in model-derived node text; not reproducible (rebuilding gives different JSON).
