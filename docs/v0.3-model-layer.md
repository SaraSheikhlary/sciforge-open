# SciForge v0.3 model layer — Milestones 1–2 (in development)

> "V0.2 remains the authority for source identity. V0.3 can interpret verified sources, but it cannot create citations."

**Status:** Milestone 1 of v0.3 (in development, not released). The v0.2 command `sciforge investigate`
is unchanged: it never reads `XAI_API_KEY`, never imports the model layer, and makes no model calls.
There is no `--with-model` flag yet; the full user-facing documentation arrives with the orchestration milestone.

## What Milestone 1 contains

| Module | Purpose |
|---|---|
| `sciforge.llm.client` | `ModelClient` protocol; `ModelMessage`, `ModelRequest`, `ModelUsage`, `ModelResponse`; `ModelError` hierarchy |
| `sciforge.llm.xai` | `XAIClient` for the xAI Responses API (`POST /v1/responses`); one HTTP attempt per call, no internal retries |
| `sciforge.llm.parsing` | Defensive payload parsing, JSON parsing, pydantic validation, strict JSON-Schema helper |
| `sciforge.llm.budget` | `BudgetLimits`, `PriceTable`, `RetryPolicy`, `BudgetTracker`, `budgeted_call` (the retry loop) |
| `sciforge.llm.audit` | `ModelCallAudit` for a local, redacted `model_calls.json` |
| `sciforge.llm.fake` | `FakeModelClient` (scripted; used by all automated tests) |
| `sciforge.config.ModelSettings` | Model-layer settings from the environment (see `.env.example`) |

## Decisions (D1–D10)

- **D1** xAI Responses API; `store: false` on every request (hard-coded); never `previous_response_id`;
  conversation state is kept locally (a repair retry resends the full message history).
- **D2** Only `verified` sources by default; `partially_verified` only by explicit opt-in, labelled in every output.
- **D3** `XAI_MODEL` is required; no default model.
- **D4** Model entailment check on by default.
- **D5** Local `model_calls.json` audit, secrets redacted; prompts/responses stored unless
  `SCIFORGE_STORE_PROMPTS=false` (then metadata, usage and hashes only). The API key and Authorization header are never stored.
- **D6** The model never sees titles, authors, DOI, PMID, URLs or other bibliographic metadata — only opaque v0.2 record IDs.
- **D7** Live xAI tests are opt-in only (`live_xai` pytest marker, deselected by default); automated tests use
  `FakeModelClient` or `httpx.MockTransport` with the network blocked.
- **D8** Per investigation: 30 API **attempts** (every HTTP attempt counts, retries after 429 / 5xx / timeouts /
  connection errors included), 10 sources, 200,000 input tokens, 2,000 output tokens per attempt, $15 spend cap.
  See "Budget accounting" below. Prices come from `SCIFORGE_PRICE_INPUT_PER_MTOK` /
  `SCIFORGE_PRICE_OUTPUT_PER_MTOK` (none shipped). If the spend cap is enabled and prices are unset, model runs
  refuse to start (configuration error; exit 4 once the CLI flag exists). `SCIFORGE_MAX_SPEND_USD=none` disables
  the cap; `0` is rejected.
- **D9** Exit codes 5 (no validated evidence / degraded) and 6 (budget exhausted) — wired in a later milestone.
- **D10** Crossref abstracts may be used for verified records without a PMID, labelled as Crossref abstracts — later milestone.

Model text can never introduce or overwrite bibliographic fields; citations are rendered by code from v0.2 records.

## Budget accounting (attempt level)

- **Retry loop location.** Clients make exactly one HTTP attempt per `complete()`. `budgeted_call` owns the retry
  loop. Before **each** attempt, retries included, it calls `BudgetTracker.reserve()`. That is a worst-case
  pre-check: estimated input tokens (characters ÷ 3 plus overhead) and the granted `max_output_tokens`, priced with
  the price table, checked against attempts, input tokens and spend. After each attempt it calls `record()` and
  writes an audit entry. Retryable errors (429, 5xx, timeout, connection error) are retried up to
  `SCIFORGE_MAX_RETRIES`, using `Retry-After` or exponential backoff. The retry happens only if the next attempt
  also fits the budget, and that check runs before sleeping. If the budget blocks a retry, `BudgetExhausted` is
  raised at once with the previous error attached (`last_error`), and a `budget_stop` audit entry is written.
- **Sticky stop.** Once any limit is reached, no further attempts are made. The exception is a refusal caused only
  by attempts held back for later stages (`keep_attempts`).
- **Recorded spend** is kept as an exact `Decimal`. Each attempt gets a `cost_source`:
  - `reported_ticks`: `usage.cost_in_usd_ticks` / 10¹⁰ (docs: `TICKS_IN_USD_CENT = 100_000_000`), e.g.
    12345678901 ticks = $1.2345678901.
  - `reported_nano`: `usage.cost_in_nano_usd` / 10⁹.
  - `price_estimate`: usage was reported but no cost field.
  - `estimated_worst_case`: no usage at all, e.g. timeouts, connection errors, or any HTTP error (including 429
    and 4xx). The pre-attempt worst-case cost and tokens are charged.
  - `unpriced`: no cost information and no prices; only possible when the cap is disabled.
- A reported cost is always the recorded spend. The price table is only an estimate.
- Failed attempts are charged conservatively because the docs don't say which rejected requests are free.
- Every attempt appears in `model_calls.json` with:
  - attempt number, stage, timestamp, outcome and HTTP status
  - retry reason, `retry_after_s` and `backoff_s`
  - usage, `cost_usd` and `cost_source`


## Milestone 2: source texts, question definition, evidence extraction

Still **not wired into the CLI** (no `--with-model`). The entry point is
`sciforge.model_pipeline.run_model_pipeline(question, records, verification, model_client=..., settings=...,
tracker=... | model_settings=...)`, which runs after v0.2 and writes, per run directory:
`source_texts.json`, `question.json`, `evidence.json`, `model_calls.json`. There are no gaps, report or
claim-entailment stages yet. v0.2 records and verification results are only read, never modified.

| Module | Purpose |
|---|---|
| `sciforge.sourcetext` | Eligibility, abstract retrieval (PubMed efetch XML, Crossref `abstract`), cap, SHA-256 |
| `sciforge.boundary` | `ModelSource` allowlist (`record_id`, `access_level`, `source_text`) and deterministic JSON |
| `sciforge.prompts` | Versioned stage instructions (`PROMPT_VERSION`) |
| `sciforge.stages.common` | `call_structured`: budgeted call → validate → one repair (full local history) |
| `sciforge.stages.question` | S1 `QuestionDefinition` (research_question, scope, assumptions, key_concepts, ambiguities) |
| `sciforge.stages.schemas` | `ModelEvidenceItem` / `ModelEvidenceBatch` (strict, no bibliographic fields) |
| `sciforge.stages.extraction` | S2, one call per source; per-item validation; code-assigned `ev_0001` ids |
| `sciforge.stages.validation` | Deterministic checks (record ids, exact quotes, enums, bibliographic keys, identifier flags) |
| `sciforge.model_pipeline` | Orchestration and output files |

**Eligibility.** Only v0.2 `verified` records by default. `partially_verified` only with
`SCIFORGE_MODEL_ELIGIBILITY=verified_or_partial`; those sources are labelled
`eligibility: partially_verified_opt_in` in `source_texts.json` and `source_identity: partially_verified` on each
evidence item. Records without an opaque `rec_…` id or without PMID/DOI are not eligible.

**Abstracts only.**
- PubMed: `efetch` (`db=pubmed`, `retmode=xml`), batched (≤ 200 ids). It uses the same `tool`/`email`/`api_key`,
  throttling, retries and redacted request log as v0.2. Labelled sections are joined as `LABEL: text`, and
  inline markup keeps its text. Result: `access_level: pubmed_abstract`.
- Crossref: `GET /works/{doi}` in the source-text layer, used only when PubMed gave no abstract. Only the
  `abstract` that Crossref returns is used (JATS tags stripped); publisher pages are never fetched. Result:
  `access_level: crossref_abstract`. If the PubMed fetch fails, there is no Crossref fallback; the source is
  recorded as `fetch_failed`.
- Every source text has `abstract_only: true`, a retrieval `status` (`ok` / `no_abstract` / `not_eligible` /
  `fetch_failed` / `parse_error` / `source_limit`), error details, a UTC `retrieved_at`, `original_chars`,
  `truncated`, and the `sha256` of the exact capped text sent to the model.
- XML safety: stdlib `ElementTree`, which never resolves external entities. Documents with `<!ENTITY` or a
  DOCTYPE internal subset are refused, and bodies are capped at 10 MB.

**Cap and ordering.**
- `SCIFORGE_MAX_SOURCE_CHARS` (default 4000, range 200–50000) caps the text, cutting at a word boundary.
- Sources are ordered: verified before partially verified, then PMID before DOI-only, then v0.2 order.
- They are admitted with `BudgetTracker.admit_sources` until `SCIFORGE_MODEL_MAX_SOURCES` (default 10) have text.
  Later candidates are not fetched.

**Model input boundary.** The model sees only the research question, the question definition and, per source,
`record_id`, `access_level`, `source_text`. Abstract text is passed unaltered, because quotes must match it
exactly. Tests inspect every request sent to `FakeModelClient` and check that no title, author, journal, year,
DOI, PMID or URL value appears, and that no such key appears either.

**Evidence items.**
- The model returns only these fields: `source_record_id`, `claim`, `quote`, `finding`, `methods`, `limitations`,
  `relevance`, `evidence_category`, `confidence`.
- `evidence_category` is one of `established` / `conflicting` / `inference` / `hypothesis`, taken from
  `agent/research_workflow.md`.
- `confidence` is one of `high` / `moderate` / `low`.
- At most 5 items per source.

**Deterministic validation.** Each item is checked on its own. Valid items are kept; invalid items are recorded in
`evidence.json` under `rejected`, with the raw model output and reasons:
- `unknown_record_id`, `record_id_not_in_request`
- `missing_quote`, `quote_too_short` (< 20 chars), `quote_not_in_source`
- `bibliographic_field`, `unexpected_field`
- `unsupported_evidence_category`, `unsupported_confidence`, `empty_claim`, `schema_violation`,
  `exceeds_item_limit`

The quote rule is an **exact, case-sensitive substring** of the capped text, with no normalisation. DOI, PMID,
PMCID, URL or arXiv strings in claim, finding, methods, limitations or relevance are **flagged** in `warnings`, not
rejected. The code sets `evidence_id`, `access_level`, `abstract_only`, `source_identity` and
`source_text_sha256`.

**Failures.**
- Invalid JSON or a structurally invalid response gets **one** repair request. It resends the full local history
  and counts as an attempt.
- Other model errors are recorded in the stage output.
- `auth_error` or `budget_exhausted` stops further model calls; the remaining sources are recorded as `skipped`.
- If S1 fails, S2 uses the raw question.

### Numeric consistency (deterministic)

- **Claim and finding.** Every number in `claim` and `finding` must appear in the exact `quote`, otherwise the
  item is rejected with `number_not_in_quote`.
- **Methods.** Every number in `methods` must appear somewhere in the supplied (capped) source text, otherwise
  `number_not_in_source`. Methods are often described in a different sentence from the quoted result.
- **Not checked.** `limitations` and `relevance`. Numbers that appear only in the quote are fine.
- **Units.** If a number carries a unit, the reference must have the same number with the same canonical unit,
  otherwise `unit_mismatch`.
  - Only spelling variants are merged: `µM`/`μM`/`uM`, `%`/`percent`, `mL`/`ml`, `h`/`hr`/`hours`, `min`/`minutes`,
    `cm2`/`cm²`/`cm^2`, `°C`/`℃`.
  - There is no unit conversion (`1 mM` ≠ `1000 µM`; `40%` ≠ `0.4`).
  - SI prefixes stay case-sensitive.
  - A number without a unit matches that number with any unit.
- **Values** are compared numerically. Supported forms:
  - thousands separators (`1,000`)
  - decimals (`0·5`)
  - `-`, `+` and the Unicode minus `−` (`-5` is not `5`)
  - scientific notation (`1e-3`, `1.5×10^6`, `1.5 x 10-6`, `10⁶`)
  - ranges (`10–20 µM`: a unit after the range applies to both ends)
- **Ignored.** Digits embedded in tokens (`CD62`, `H2O`, `IL-6`, `TNF-α`, `3D`, `5HT`) and DOI/PMID/URL-like
  strings (these are flagged separately). Standalone numerals such as `type 2`, `day 3` or `n = 12` are counted.
- **Rejection details** give the field, the normalised value and the unit (e.g. `{"field": "claim",
  "value": "45", "unit": "%"}`). Numbers are diagnostic, not bibliographic, and identifier-like strings are
  removed before numbers are extracted.

### Validation precedence

`stages.validation.combine_support(DeterministicResult, model_label)`:
- A deterministic failure (unknown or not-in-request record id, non-exact quote, bibliographic field, unsupported
  category or confidence, numeric or unit inconsistency, schema problems) is always `rejected` /
  `rejected_deterministic`, whatever label a model gives.
- A model label can only lower an item that passed: `supported` keeps it `accepted`; `partially_supported`,
  `unverifiable` or `not_supported` make it `downgraded`. An unrecognised label counts as `unverifiable`.
- Accepted items currently carry `support.final_label = passed_deterministic`. The model entailment stage comes
  in a later milestone and must go through this function.

### Rejected output handling

- **`evidence.json`** stores only safe diagnostics for each rejected item:
  - reason codes
  - the code-supplied `call_record_id` and `item_index`
  - `source_record_id`, only if it was one of the supplied ids
  - `validation_status`
  - field names present or missing, field lengths and quote length
  - the names of any bibliographic keys (never their values)
  - SHA-256 of the raw item
  - numeric value and unit details
- It never stores claim, quote or finding text, invented titles or DOIs, or other identifiers. An unknown record
  id is hashed unless it has the opaque `rec_` form. Unsupported enum values are echoed only if they are on a
  short list of harmless words; otherwise they appear as `[redacted]`.
- **`model_calls.json`**: for an extraction call that had rejected items, failed validation or needed a repair,
  the stored model output is replaced, not just redacted. Those entries are marked `model_output_redacted: true`
  and `redaction_mode: "safe_diagnostics"`.
  - `response_text` becomes a structured JSON summary. It contains the call record id, the original response
    SHA-256 and length, and the parse status.
  - Each accepted item appears as `evidence_id` plus its raw-item hash.
  - Each rejected item appears only as safe diagnostics: an opaque source id (or hash + length), reason codes and
    safe reason details, validation status, field names, presence and lengths, quote length, raw-item hash,
    numeric/unit diagnostics, and bibliographic key names.
  - A response that failed validation shows only its structure (e.g. `invalid_json`, top-level key names, item
    count).
  - Assistant output echoed in repair requests becomes `{"echoed_model_output": "[redacted]", "sha256", "length"}`.
  - No claim, quote, finding, methods, limitations, relevance or other free text from these calls is stored.
    Clean calls are stored unchanged.
- **Leak check**: `sciforge.output_guard.find_leaks(run_dir, needles)` byte-searches every file in a run
  directory except `debug/`. That covers `source_texts.json`, `question.json`, `evidence.json`, `model_calls.json`
  and any later file such as `report.md`. Tests use unique sentinel strings in rejected items to show that none
  of them reach normal outputs.
- **`SCIFORGE_DEBUG_KEEP_REJECTED_RAW`** (default `false`) is an explicit local debug opt-in. When it is on, the
  raw rejected items and the full unredacted responses and echoed messages (with `response_sha256` for
  correlation) are written only to `runs/<stamp>/debug/rejected_raw.json`, which
  starts with a warning. `evidence.json` and `model_calls.json` stay redacted even with debug on. Debug records can
  be matched to diagnostics through `raw_item_sha256`.
